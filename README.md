# 1. Зачем нужна эта система?

Целью разработки этого проекта является увеличение эффективности банковской системы при работе с мошенническими транзакциями.

Это позволит:

- уменьшить **финансовые и репутационные риски**, связанные со штрафами за пропуск фродовых транзакций;
    
- уменьшить **отток недовольных клиентов**, чьи транзакции были ложно классифицированы как мошеннические;
    
- уменьшить **нагрузку на аналитиков**, которые вручную обрабатывают часть транзакций, засчитанных базовой системой как мошеннические.
    

---

# 2. Результат работы системы

Данная система для каждой транзакции на основании её признаков будет классифицировать, является ли она мошеннической.

Результат работы системы будет отслеживаться при помощи следующих трёх метрик:

- **Выгода от выполнения транзакций** — банк получает некоторую долю от выполненной транзакции.
    
- **Величина штрафа в конце месяца** — отражает суммарный размер штрафа, который получает банк в конце каждого месяца за пропущенные мошеннические транзакции. Успешная работа антифрод-системы должна уменьшать эту метрику.
    
- **Нагрузка на команду аналитиков** — отражает сумму, потраченную на работу команды аналитиков для ручной перепроверки части транзакций. Аналогично, успешная работа системы должна уменьшать объём транзакций, которые отправляются на ручную обработку.
    

Стоимость системы будет складываться из двух пунктов:

- затрат на работу команды специалистов, которая будет разрабатывать и поддерживать систему;
    
- затрат на инфраструктуру системы: облачные технологии, вычисления модели, обеспечение безопасности и т. д.
    

Ключевым критерием работы системы также является **скорость работы**.

Время обработки каждой транзакции не должно превышать некоторый порог $T$, чтобы не ухудшать клиентский опыт использования услуг банка.

Работа антифрод-системы будет считаться успешной, если выгода от её введения превысит стоимость затрат на её разработку через $N$ месяцев.

# 3. Как достигнуть поставленной цели?

В терминах машинного обучения это задача **бинарной классификации с сильным дисбалансом классов**.

С точки зрения бизнес-задачи нужно увеличить количество заблокированных фродовых транзакций, что соответствует метрике **Recall**.

При этом следует гарантировать минимальное количество ложных блокировок обычных транзакций, что соответствует метрике **Specificity**.

Поэтому в качестве метрики проверки качества модели машинного обучения стоит взять **Recall@Specificity**, которая позволяет максимизировать Recall при условии неухудшения Specificity.

Таким образом, предполагается, что данная ML-метрика коррелирует с бизнес-метриками.

## Набор данных

Для обучения моделей машинного обучения был выбран открытый набор данных с платформы  Kaggle:

[https://www.kaggle.com/datasets/ealaxi/banksim1/data](https://www.kaggle.com/datasets/ealaxi/banksim1/data)

BankSim — синтетический датасет, в котором нормальное поведение генерируется на основе агрегированной статистики реального банка, а мошенническое поведение моделируется отдельно посредством заранее заданных fraud-сценариев.

|Column Name|Description|
|---|---|
|`step`|Единица времени: 1 step = 1 час. Симуляция охватывает 30 дней (744 шага).|
|`type`|Тип транзакции: `CASH-IN`, `CASH-OUT`, `DEBIT`, `PAYMENT`, `TRANSFER`.|
|`amount`|Сумма транзакции в симулируемой валюте.|
|`nameOrig`|Анонимизированный идентификатор отправителя.|
|`oldbalanceOrg`|Баланс отправителя до выполнения транзакции.|
|`newbalanceOrig`|Баланс отправителя после выполнения транзакции.|
|`nameDest`|Анонимизированный идентификатор получателя.|
|`oldbalanceDest`|Баланс получателя до выполнения транзакции, если применимо.|
|`newbalanceDest`|Баланс получателя после выполнения транзакции, если применимо.|
|`isFraud`|Бинарный признак: `1` — транзакция является мошеннической, `0` — обычной.|
|`isFlaggedFraud`|Бинарный признак: `1`, если транзакция превышает заданный порог (например, > 200 000).|
